# Witness Bundle Samples - Agent 9 Negative Test Injection

This directory contains sample witness bundles generated by the negative test suite.

## Purpose

Witness bundles are JSON artifacts that provide reproducible evidence of divergence detection.
They accompany CBOR receipts and enable:
1. Reproduction of failure scenarios
2. Verification of fail-closed behavior
3. Auditing of divergence detection logic

## Files

- `scenario_a_simd_divergence.json` - SIMD mode divergence (AVX-512 vs Scalar)
- `scenario_b_epoch_contamination.json` - Cross-epoch cache contamination
- `scenario_c_cache_log_divergence.json` - Cache decision log divergence (HIT vs MISS)
- `scenario_d_nondeterminism.json` - Result bytes non-determinism

## Structure

All witness bundles conform to the `WitnessBundle` schema:

```json
{
  "scenario": "string (scenario identifier)",
  "expected_verdict": "FAIL | PASS",
  "actual_verdict": "FAIL | PASS",
  "divergence_detected": "boolean",
  "receipt_path": "string (path to CBOR receipt)",
  "rerun_command": "string (command to reproduce)",
  "evidence_hash": "string (BLAKE3 hash)",
  "timestamp": "string (ISO 8601 timestamp)",
  "evidence": {
    // Scenario-specific evidence fields
  },
  "failure_details": {
    "failure_class": "string (FailureClass enum variant)",
    "is_blocking": "boolean",
    "description": "string (human-readable description)"
  }
}
```

## Validation

All witness bundles:
- ✅ Are valid JSON (parseable by `serde_json`)
- ✅ Contain rerun commands for reproducibility
- ✅ Have deterministic evidence hashes
- ✅ Map to CBOR receipts in `/tmp/qlever-verification-receipts/`

## Generating Witness Bundles

Run the negative test suite:

```bash
cd /home/user/qlever/qlever-verification
cargo test --test negative_tests -- --nocapture
```

Witness bundles are generated in temporary directories during test execution.
The samples in this directory are representative examples.

## Usage

### Reproduce a scenario:
```bash
# Extract rerun command from witness bundle
jq -r '.rerun_command' scenario_a_simd_divergence.json
# Output: cargo test --test negative_tests -- scenario_a_simd_mode_divergence --nocapture
```

### Verify evidence hash:
```bash
# Compute BLAKE3 hash of scenario name
echo -n "scenario_a_simd_mode_divergence" | b3sum
# Compare with witness bundle's evidence_hash field
```

### Inspect failure details:
```bash
jq '.failure_details' scenario_a_simd_divergence.json
```

## Invariants

1. **Determinism**: Same scenario → same evidence_hash
2. **Reproducibility**: rerun_command always produces same divergence
3. **Fail-Closed**: expected_verdict == actual_verdict == "FAIL" for all negative tests
4. **Traceability**: receipt_path links to CBOR receipt with full evidence
